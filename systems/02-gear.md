# 02 · 装备磨损与维护

## 目标

让现有装备不再只是“有 / 没有”的布尔值：头灯会掉电、登山杖会磨损、外层会失效、
睡袋和防潮垫会影响营地恢复。玩家需要在“继续用、营地维护、减重”之间权衡。

不改路线、不新增章节、不新增选择按钮。只写：

- `systems/02-gear.js`
- `systems/02-gear.test.cjs`

禁止修改 `game.html`。

## 状态

初始化到 `st.sys.wear`，只记录本局实际携带的耐用品：

```js
{
  lamp: 100,          // 头灯电量
  poles: 100,         // 登山杖磨损
  jacket: 100,        // 外层防风雨性能
  sleepingbag: 100,   // 睡袋保暖
  mat: 100            // 防潮垫
}
```

- 未携带的装备记为 `0`，不要凭空增加。
- 范围 0–100，整数；使用 `ctx.r2` / `ctx.clamp` 统一取整和夹取。
- 同步现有布尔值：
  - `lamp <= 0` → `st.lamp = false`
  - `poles <= 0` → `st.poles = false`
  - `jacket <= 0` → `st.jacket = false`
  - 维护后恢复对应布尔值（若初始携带）。
- 同一 seed/路线/配装必须得到同一初始磨损。

## 规则（`onChoice`，核心结算之后）

每个选择最多结算一次：

1. **头灯**
   - `ch.nightSafe` 或 `card.kind === 'night'` 且实际使用头灯：`lamp -12`。
   - 若 `lamp` 降到 0：`st.lamp = false`，追加
     `头灯电量耗尽：后续夜行按无灯处理。`
   - `lamp <= 25` 时，`trade` 标注 `头灯电量低`。

2. **登山杖**
   - `card.kind === 'terrain'` 或 `ch.detour`：`poles -8`。
   - 降到 0：`st.poles = false`，追加
     `杖尖磨平：后续不再享受省力加成，但仍可选择安全路线。`
   - 注意：核心的 `choiceStamina` 读取 `st.poles`；本系统只负责在归零时关闭它。

3. **外层**
   - `st.flags.wet`、`weather === 'storm'` 或 `ch.heat` 时：`jacket -5`。
   - 降到 0：`st.jacket = false`，追加
     `外层防风雨性能失效：后续散热结算不再获得外层减免。`
   - 不要修改 `st.temp` 本身，核心已经结算；本系统只改变后续能力。

4. **营地维护**
   - `ch.camp && !ch.poorCamp`：所有携带的耐用品 `+12`（上限 100），
     恢复对应布尔值，追加
     `营地维护：可修复的装备恢复少量耐久；这不是现实维修保证。`
   - 同一晚只维护一次；`poorCamp` 不维护。
   - 维护不额外扣时间，时间已包含在营地行动里。

5. **睡眠装备**
   - 在 `ch.camp && !ch.poorCamp` 结算后：
     - `sleepingbag < 30` 或 `mat < 30`：`st.stamina -4`；
     - 两者都 `< 30`：`st.stamina -8`，取一次，不叠加两次。
   - 文案：`睡眠装备损耗影响恢复；游戏只扣少量体力，不模拟真实失温。`
   - 不要让体力低于 0。

6. **其他选择**：不改变耐久。

## 面板与副标题

`panelHTML(st, ctx)` 返回一行，只显示携带且低于 90 或已失效的装备，避免刷屏：

```html
<p class="statusline">装备 · 头灯 64% / 登山杖 32% / 外层 完好 / 睡袋 88%</p>
```

- 所有名字是常量；数值用 `Math.round` 后插入。
- 不要新增 `<style>`；沿用现有 `statusline` 样式。

`trade(st, ch)` 追加短标签：

- `ch.nightSafe` → `头灯 ${lamp}%`（无灯则 `无头灯`）
- `card.kind === 'terrain' || ch.detour` → `登山杖 ${poles}%`（失效则 `登山杖失效`）
- `ch.camp` → `营地可维护`
- 其他返回空字符串。

## Echo

`echo(st, card, ctx)`：

- `alerts`：
  - 任一装备 `0 < wear <= 25`：`装备接近失效：继续使用会把风险留到后面，营地维护优先。`
  - 任一装备 `=== 0` 且本局携带过：`已有装备失效：本局后续不再享受对应加成，必要时中止。`
- `science`：
  `装备只能降低部分风险，不能替代路线判断、休息和撤退；损坏的装备不要假设仍能提供保护。`
- 不写现实品牌、价格或维修教程。

## 测试（Node 原生 assert）

`02-gear.test.cjs` 至少覆盖：

1. 三条路线、带/不带对应装备时初始化正确；未携带的耐久为 0。
2. 夜行、碎石、暴雨、营地分别只扣对应装备，且不越界。
3. 耐久归零后 `st.lamp/poles/jacket` 为 false；维护后恢复。
4. 营地维护只加一次，`poorCamp` 不维护；睡眠装备低耐久只扣一次体力。
5. 同一 seed/路线/配装初始化一致；100 个 seed 不出现 `NaN`、负数。
6. `panelHTML` / `trade` 不出现 `undefined`，不插入未转义动态文本。
7. 不修改 `st.water`、`st.waste`、`st.leg`、路线长度。
